An Khang Pharmacy | 2026 | Product Manager

Automating the An Khang Online health dashboard

Problem

Whenever anyone needed health metrics for the web and app, they had to ask the PM team to prepare them. The PM team then had to pull figures from several sources, type them in by hand for about 15 to 20 minutes every day, and take screenshots or export PDFs from the report file to send to stakeholders. The monthly report took 1 to 3 hours if done in one go, but with other work in between it could stretch to 3 to 4 days.

Role

I was responsible for the whole project: spotting what could be automated in daily work, defining the approach with AI's help, consolidating the data sources, writing Google Apps Script (GAS) and the HTML report, publishing on GitHub Pages, improving it from feedback, and writing the handover documentation. I had no coding experience before, so every part was built with AI, step by step.

Approach

It started by replacing manual data entry with automation using GAS. GAS runs twice a day, cleans the data, writes it to one shared store, and connects through an API to pull in sessions and conversion rate from GA4. The report is a single HTML web page, using the design language of the group's annual reports so leadership finds it familiar and easy to read. The sales team uses the daily report to plan promotions or shift budget toward a weak channel such as marketplaces; the PM team tracks traffic and app downloads to propose traffic-driving features or app-install programs; the CEO and CTO read the monthly report to set direction.

Three key decisions

  • Extend from the daily report to the monthly report. I realized the monthly report is essentially the daily report plus growth commentary and next month's work plan, so one shared data store could serve both.
  • Create an HTML page that every stakeholder can open themselves, replacing screenshots and PDFs sent by hand, so they can check the report whenever they need it.
  • Use free, password-protected tools, the best fit for internal use (Google Sheets, GAS, GitHub Pages). The only cost was a one-time cost at build, for an AI plan.

Challenges

The code from the first AI model was not good enough, so I had to switch both the model and the AI tool and rewrite from scratch. The new AI took over the old code, which led to logic errors and inconsistent coding styles, and the numbers were far off at acceptance. To fix it, I compared against the manual numbers; whenever something was off, I had the AI find the error and rewrite, then review the whole codebase for consistency, add comments, and write the handover documentation.

After go-live

The CTO reviewed the report in the regular monthly meeting and suggested adding a section on work done and planned, which the first version lacked, so managers would have the full picture to decide. The sales team used the report to present the online business to the BOD. Other sites in the group also looked to the approach and asked for the template to apply to their own sites.

Lessons

  • With daily work that has become familiar and turned into habit, it is hard to notice inefficiency in how it is done. So it takes close observation and reflection deep enough to find what can be improved.
  • If I did it again, I would choose the AI tool carefully from the start and keep one strong coding AI throughout the project, so the code stays consistent and doesn't need rewriting.

Results

The daily report went from about 15 to 20 minutes of manual entry per day to zero (fully automated). The monthly report went from 1 to 3 hours of work to about 5 minutes of review and commentary. That saves roughly 11 to 15 hours a month, or 132 to 180 hours a year.
